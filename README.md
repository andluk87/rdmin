# RemoteAdmin — Windows Server + Windows Client

Два отдельных приложения для Windows x64. **Веб-приложения и центрального Backend нет.**
Сервер показывает экран и выполняет разрешённые действия в интерактивной сессии пользователя.
Клиент подключается напрямую по IP/DNS. Установка .NET на целевом ПК не требуется: публикация self-contained.

**Статус: исходники прототипа, сборка и испытания не выполнялись по просьбе заказчика.**
Это не принятый по исходному ТЗ MVP. Реализованный scope и ограничения: [docs/STATUS.ru.md](docs/STATUS.ru.md).
Исходное ТЗ сохранено в [docs/SPEC.ru.md](docs/SPEC.ru.md); более позднее требование заказчика исключает Web/Backend.

## Сборка на VPS с Docker

Нужны Linux x64, Docker с BuildKit, доступ к Microsoft Container Registry, Debian и NuGet.
Ориентир свободного диска — 8 GiB; сама сборка может потребовать несколько GiB RAM.
Из корня репозитория:

```bash
bash scripts/build-vps.sh
```

Результат появится **в корне репозитория**:

- `RemoteAdminServer-0.3.1-win-x64.zip`
- `RemoteAdminClient-0.3.1-win-x64.zip`
- `RemoteAdminServer-0.3.1-win-x64.msi`
- `RemoteAdminClient-0.3.1-win-x64.msi`
- `SHA256SUMS`

Для вывода непосредственно в `/root` на VPS (если есть права):

```bash
OUTPUT_DIR=/root bash scripts/build-vps.sh
```

Docker собирает Windows EXE, native DXGI DLL и MSI из Linux. Windows-контейнер не нужен.
BuildKit собирает Server и Client параллельно в изолированных стадиях. Число доступных CPU определяется через `nproc`; каждому MSBuild выделяется половина этого числа (с округлением вверх). Упаковка двух приложений также выполняется параллельно. Ограничение Docker на CPU не задаётся. Загрузка 100% не гарантируется: загрузка пакетов, последовательные шаги и кэш могут ограничивать параллелизм. При нехватке RAM уменьшите число потоков, например `BUILD_JOBS=2 OUTPUT_DIR=/root bash scripts/build-vps.sh`.
Сертификат подписи кода не предоставлен: MSI/EXE не подписаны, SmartScreen может показать предупреждение.
Не отключайте защиту Windows. Для распространения релиза требуется доверенная подпись и проверка безопасности.

## Подключение — версия 0.3.0

**Настройте сервер один раз:**

1. Запустите `RemoteAdminServer.exe`, откройте «Пользователи и права…».
2. Создайте учётную запись RemoteAdmin: логин, пароль от 12 символов, просмотр / управление / файлы / буфер / чат.
3. При необходимости явно снимите «Запрашивать согласие перед каждой сессией» и подтвердите постоянный доступ. По умолчанию согласие требуется.
4. Выберите метод «Учётные записи RemoteAdmin», задайте порт и сохраните настройки. Затем включите доступ. Разрешите порт в Windows Firewall только для доверенных сетей или адресов.

**На клиенте:**

1. Укажите IP/DNS сервера и порт, нажмите «Подключиться».
2. При первом соединении сверьте и подтвердите ключ сервера. Он сохранится и будет проверяться автоматически; изменение ключа блокирует вход до ручного выяснения причины.
3. Введите серверный логин и пароль. Доступные функции определяет серверная учётная запись. Код приглашения для такого входа не нужен.

Метод аутентификации сообщает сервер после защищённого соединения. Учетные записи RemoteAdmin не являются пользователями Windows; интеграция Windows/AD/SSPI пока не реализована. Клиент не сохраняет пароль.

Разовые приглашения остаются отдельным режимом «Одноразовые приглашения» или «Учётные записи и приглашения». Для них действует код на 5 минут и обязательное локальное согласие. В клиенте этот режим находится в «Ключ и приглашение…».

Настройки сервера, учётные записи и PBKDF2-проверочные значения защищены DPAPI CurrentUser в `%LOCALAPPDATA%\RemoteAdmin\Server\access.dpapi`. Изменение прав, пароля, метода входа или удаление пользователя прекращает активный сеанс. Пароль через TLS передаётся только после подтверждения ключа сервера, в логи не попадает. Ограничение: пять попыток входа в минуту на IP и 60 суммарно.

Оба приложения нужно обновить до **0.3.0**: обмен при входе изменился. Это по-прежнему интерактивный сервер, а не Windows Service: он должен быть запущен в пользовательской сессии. Доступ без разового согласия не означает запуск службы или обход экрана блокировки Windows.

Полный ZIP нужно распаковать целиком: EXE использует библиотеки из своего каталога.
MSI создаёт ярлык в меню Пуск; приложение запускается вручную. Удаление — через «Установленные приложения» Windows.

## Функции

- Захват выбранного монитора через DXGI Desktop Duplication, GDI fallback.
- JPEG-кадры в TLS-потоке; адаптация качества вручную: 5/10/20 FPS.
- Нормализованные координаты мыши, кнопки, колесо, клавиатура; отпускание ввода при разрыве/потере фокуса.
- Проверка прав на сервере для каждого действия; View Only, чат, разрешаемый текстовый буфер обмена.
- Общая папка `Documents\RemoteAdminShare`: список, создание папок, rename, upload/download, подтверждаемое удаление.
- Чанки до 4 MiB, докачка через `.ra-part`, SHA-256 и лимит файла 2 GiB.
- Адресная книга клиента без кодов доступа и локальный аудит метаданных.

Для интернета используйте существующий VPN либо настройте проброс TCP-порта и ограничение источников в firewall.
Автоматических NAT traversal, P2P broker и Relay здесь нет. Приложение не требует VPS для работы после сборки.

Протокол и модель безопасности: [docs/SECURITY.ru.md](docs/SECURITY.ru.md).
Ручная приёмка: [docs/TESTING.ru.md](docs/TESTING.ru.md).

Подробный лог сборки сохраняется рядом с артефактами в `remoteadmin-build.log`. Проверка HTTPS NuGet выполняется перед restore, а restore выводит адреса и результаты загрузок. NuGet-кэш сохраняется в Docker builder; restore-кэш слоя обновляется при изменении файлов проектов или проверки сети. Первая сборка должна скачать Windows runtime. ZIP использует быстрое сжатие (уровень 1), поэтому может быть немного больше.

Если NuGet отвечает на VPS, но Docker bridge выдаёт TLS timeout, на Linux можно использовать сеть хоста только для команд сборки:

```bash
BUILD_NETWORK=host OUTPUT_DIR=/root bash scripts/build-vps.sh
```

Это передаёт `--network host` BuildKit и не меняет firewall/настройки Docker daemon. HTTPS-проверка сертификатов остаётся включённой. Режим предоставляет командам Dockerfile доступ к сетевому пространству хоста; применяйте только к доверенному Dockerfile. По умолчанию используется обычная сеть Docker.

## Новый интерфейс

Клиент: боковой список компьютеров с поиском, форма с подписями и проверкой полей, вставка приглашения, отдельный экран сеанса, сворачиваемый чат и полноэкранный режим с выходом по Escape. Кнопки файлов и ввода учитывают выданные права. Сервер: отдельные карточки доступа, приглашения и разрешений, срок действия кода, кнопки копирования и открытия общей папки, заметное завершение сеанса. Файловый менеджер: два независимых списка с адресными строками, переходом наверх, индикатором прогресса, скоростью, оставшимся временем и отменой.

Чтобы заполнить адрес, порт, ключ и код без ручного набора: на сервере включите доступ, проверьте доступный оператору адрес и нажмите «Копировать приглашение»; в клиенте нажмите «Вставить приглашение». Приглашение содержит одноразовый код: отправляйте его только доверенному оператору.

Изменения интерфейса в этой задаче не собирались и не запускались на Windows. После сборки проверьте окно подключения, согласие, сеанс, поиск компьютеров, масштабирование Windows 100/150/200% и файловый менеджер.

Текущая версия: **0.3.1**. Единый источник версии — `desktop/Directory.Build.props`: упаковщик читает из него версию MSI и имён архивов. Она также показана в заголовках приложений. MSI содержит правила обнаружения предыдущих версий с сохранением UpgradeCode; обновление поверх 0.1.0 нужно проверить на Windows. Перед обновлением закройте Server и Client. Старые ZIP/MSI в `/root` автоматически не удаляются — выбирайте файлы с `0.3.1` в имени.

### Исправления 0.3.1

Загрузка серверного TLS-ключа использует `UserKeySet`, совместимый со Schannel, вместо `EphemeralKeySet`; закрытый PFX по-прежнему защищён DPAPI. Общая папка открывается только при файловой операции. Отмена/таймаут одного сеанса больше не прекращает accept-loop сервера. Безопасные диагностические записи с этапом, типом исключения и HRESULT сохраняются в `%LOCALAPPDATA%\RemoteAdmin\Server\diagnostics.jsonl` и `Client\diagnostics.jsonl`; тела сообщений и тексты исключений не записываются. На сервере есть кнопка «Диагностика». Исправления не собирались и не проверялись на Windows в этой задаче.
