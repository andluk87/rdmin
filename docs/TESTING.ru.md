# Проверка после сборки на VPS

Эти проверки подготовлены для выполнения заказчиком. В текущей задаче они не запускались.

1. Выполнить `bash scripts/build-vps.sh` на Linux x64 VPS. Проверить четыре артефакта и `sha256sum -c SHA256SUMS`.
2. На Windows 10/11 и Server 2019/2022/2025 проверить запуск ZIP целиком и установку/удаление MSI. Проверить Start Menu, DLL DXGI и работу без установленного .NET.
3. На двух Windows-машинах в LAN: включить Server, передать отпечаток и код, подключить Client. До локального согласия убедиться в отсутствии изображения и управления.
4. Изменённый отпечаток, неверный/истёкший/использованный код должны отклоняться. Отказ в consent не должен открывать экран.
5. Проверить View Only: mouse/key не исполняются; снять локальный флажок «Управление» — сессия разрывается. Повторное подключение требует нового кода и согласия.
6. Проверить клики, drag, колесо, Ctrl/Shift, русскую/английскую раскладку, отпускание при потере фокуса клиента, обрыве сети, закрытии клиента и остановке сервера.
7. Два монитора, разные DPI, отрицательные координаты, портретный монитор, 1920×1080: правильный монитор, соотношение сторон и координаты. Проверить GDI fallback и DXGI отдельно. UAC не должен обходиться; разрыв/ошибка допустимы для этого прототипа.
8. Передать 100 MiB, проверить SHA-256. Начать 2 GiB, прервать, заново открыть сессию и продолжить тот же файл. Изменённый частичный файл должен отклониться на SHA-256. Проверить пустой файл, отмену, upload/download, занятый файл, отсутствие overwrite.
9. Проверить `../`, `C:/`, UNC, ADS, reparse point, junction, hardlink, зарезервированные имена и выход за общую папку: отклоняются. Проверить local ACL отказ. Подтвердить удаление на обеих сторонах, отказ сохраняет файл.
10. Буфер: Unicode, размер 1 MiB, запрет при отсутствии права, отсутствие циклов. Чат не должен попадать в audit.
11. Разорвать сеть и закрыть сервер: удерживаемые кнопки отпускаются, клиент очищает изображение. Повторное подключение — новая подтверждаемая сессия.
12. Проверить malformed JSON, неверную версию, длину >8 MiB и неизвестный тип пакета: безопасное завершение, без исключения процесса и утечки ключа.

## Автоматические исходники проверок

`tests/Checks.csproj` — Windows console harness для протокола, DPAPI identity и файловой политики. На Windows с .NET SDK 8:

```powershell
dotnet run --project tests/Checks.csproj -c Release
```

Это запускает сборку и тесты только по вашей команде на Windows; в данной задаче не выполнялось.

## Фиксация результата

Запишите версию Windows, GPU/драйвер, режим DXGI/GDI, DPI/мониторы, сеть, размеры файлов, SHA-256, результаты каждой проверки и время. Производительность и соответствие исходному ТЗ не заявляются до измерений и реализации пунктов STATUS.ru.md.

## Проверки нового интерфейса

- Сервер: до включения доступ закрыт, после включения можно скопировать приглашение; после подтверждения видны состояние и кнопка завершения.
- Клиент: вставить приглашение без ручного ввода, проверить пустые/неверные поля и отмену ожидания; сохранить компьютер без кода, найти по имени/адресу, удалить с подтверждением.
- Сеанс: недоступные права блокируют кнопки, чат открывается и закрывается, есть индикатор нового сообщения, Escape возвращает из fullscreen, завершение возвращает на форму подключения.
- Файлы: обе адресные строки, переход наверх, сохранение выбранных направлений, недоступность кнопок без выбранного файла, прогресс/скорость/ETA, отмена и повтор для докачки.
- Масштаб Windows 100%, 150%, 200% и изменение размеров окон: подписи читаются, поля не перекрываются, длинная форма прокручивается, toolbar переносится.

Новые проверки не запускались: запрет на локальную сборку заказчика сохраняется.

## Приёмка аутентификации 0.3.0

1. С чистой конфигурацией выбран вход по учётным записям, приглашения скрыты; без включённого пользователя сервер не включает доступ.
2. Создать пользователя с паролем, закрыть/открыть сервер: логин, права, порт и метод входа сохраняются, пароль не хранится открыто.
3. В клиенте указать только IP/порт, отклонить первый ключ — пароль не отправляется. Подтвердить сверенный ключ, войти правильными данными. При повторе ключ не спрашивается. Изменённый ключ отклоняется.
4. Проверить неверный пароль, неизвестного и отключённого пользователя; общий отказ, отсутствие данных сеанса. После пяти попыток на IP новые временно отклоняются.
5. Для записи «только просмотр» ввод не исполняется даже при запрашиваемом полном контроле. Отдельно проверить файлы, чат и буфер по серверным правам.
6. По умолчанию требуется согласие. Явно разрешить без согласия конкретному пользователю — корректный вход без повторных подтверждений; окно сервера показывает активный доступ, остановка завершает сеанс.
7. Во время сеанса изменить пароль/права/метод входа, отключить или удалить пользователя: доступ прекращается, клавиши отпускаются.
8. При включённых приглашениях проверить их код и обязательное согласие; в режиме «Учётные записи» приглашение не принимается.
9. Обновить оба приложения до 0.3.0; старый протокол не должен приводить к открытию экрана без проверки.

Исходники автоматических проверок аккаунтов, сохранения политики, ограничения попыток и замены pin добавлены в harness; они не запускались по запрету на локальную сборку.

## Регрессия EOF / TLS (0.3.1)

Проверить вход на двух Windows-машинах с существующим DPAPI-сертификатом и с новой identity. Проверить отмену окна входа, timeout, локальное завершение сеанса и последующее новое подключение без перезапуска сервера. Вход без права Files должен работать при недоступной общей папке; ошибка папки должна возвращаться только в файловой операции. При неуспешном TLS сохранить diagnostics.jsonl обеих сторон и версии Windows. Пароли/код/JSON не должны попадать в диагностику. Эти проверки не запускались в текущей задаче.

## Регрессия раннего release (0.3.2)

На обновлённых клиенте и сервере подключиться по IP/порту: окно логина должно оставаться открытым без EOF. До ввода пароля переключиться Alt+Tab, вернуться, ввести правильные данные и проверить вход. Отклонить/отменить вход и повторить. После подтверждённого сеанса удержать клавишу и перевести фокус из удалённого экрана: отпускание должно продолжать работать. Ранние команды от старого клиента сервер обязан отклонять без запуска экрана. Эти проверки не запускались в текущей среде.
