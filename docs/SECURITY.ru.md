# Протокол и безопасность

## Доверие

При первом запуске Server создаёт ECDSA P-256 сертификат с SHA-256, срок 2 года. PFX сохраняется через Windows DPAPI CurrentUser в `%LOCALAPPDATA%\RemoteAdmin\Server\identity.dpapi`. Закрытый ключ не передаётся.
Клиент проверяет 64-символьный SHA-256 всего DER сертификата. Можно передать pin заранее либо подтвердить его при первом соединении. Новый ключ требует явного доверия, изменившийся сохранённый ключ блокирует вход.
Имя/DNS не является идентичностью: идентичность определяется точным pin сертификата и сроком его действия.
Используется self-signed pinning, не публичная PKI; OCSP/CRL для такого сертификата не применяется. Истечение требует локально удалить/заменить identity и снова передать новый отпечаток.

Основной режим — серверные учётные записи RemoteAdmin. Пароли проверяются PBKDF2-HMAC-SHA256 (600 000 итераций, соль 16 случайных байтов, результат 32 байта, сравнение FixedTimeEquals). Клиент передаёт пароль внутри TLS, не сохраняет его и не пишет в аудит. Файл конфигурации сервера `access.dpapi` защищён Windows DPAPI CurrentUser и атомарно заменяется при сохранении.

Права, включение/отключение пользователя и требование согласия задаются только локально на сервере. Изменение настроек, пароля, прав или удаление записи прерывает сеанс. Отсутствующие и отключённые пользователи проходят эквивалентную KDF-проверку с общим сообщением отказа. На IP допускается пять попыток за минуту, суммарно 60. Это ограничение не защищает от распределённого DoS.

Доступ без разового согласия требует отдельного явного действия в редакторе пользователя и подтверждения предупреждения. Сервер остаётся видимым приложением в текущей пользовательской сессии, его можно выключить локально. Автозапуск службы и скрытые подключения не добавлены.

При первом подключении без заранее известного ключа TLS используется предварительно: клиент не отправляет учётные данные и команды до явного подтверждения пользователем SHA-256 сертификата. Сверьте ключ независимым доверенным каналом. После подтверждения pin привязывается к адресу и порту в `trusted-servers.json`. Изменившийся ключ не принимается автоматически. Это TOFU с ручной проверкой при первом входе, а не публичная PKI.

Одноразовые приглашения — отдельный метод, выключенный по умолчанию. Их код содержит 128 случайных битов, действует 5 минут, расходуется до запроса согласия, требует локального подтверждения. Имя оператора в этом режиме не удостоверено; в режиме учётной записи аудит использует логин, проверенный сервером.

Все приложения должны запускаться обычным пользователем. Конфигурацию и ключи может изменять владелец текущей Windows-учётной записи; это не модель изоляции от администратора или самого владельца ОС.

## Транспорт

Порт TCP 4899 по умолчанию. TLS 1.2/1.3 штатного SslStream; 1.2 нужен для Windows 10.
Внутри TLS: 4 байта big-endian длины JSON UTF-8, затем JSON, максимум 8 MiB.
Envelope: `{version:1,type,id,data}`. Недопустимые версии, неизвестные сообщения и превышения лимитов завершают сеанс.
Данные файлов и JPEG кодируются base64. Видео идёт по тому же надёжному TLS-потоку: это проще WebRTC, но крупные файлы увеличивают задержку ввода/видео.
Очередь записи защищена семафором; чанк/кадр отправляется с backpressure. Heartbeat 10 секунд, idle read 35 секунд, write timeout 15 секунд. Сбой завершает управление и отпускает удерживаемые клавиши/кнопки.

Порядок: TLS → проверка/первое подтверждение pin → `auth.options` (разрешённые сервером методы) → `hello` (логин/пароль либо код, запрашиваемые функции) → проверка и согласие согласно серверной политике → `welcome` → данные. Учётные данные не отправляются до подтверждения pin.
`welcome`: session UUID, пересечение запрошенных и локальных прав, дисплеи.
Сообщения: `frame`, `mouse`, `key`, `text`, `release`, `viewonly`, `quality`, `chat`, `clipboard`, `file`, `file.reply`, `ping`, `pong`, `error`, `terminate`.
`file.reply.id` совпадает с `file.id`; одновременно рекомендуется одна передача.
Команды ввода/файлов/буфера/чата проверяются на сервере независимо от UI клиента. Изменение локальных разрешений разрывает активный сеанс. Переключение клиента в View Only безвозвратно снимает Control на сервере для текущей сессии; возврат управления требует нового подтверждённого подключения.

## Файлы

Только `%USERPROFILE%\Documents\RemoteAdminShare` под ACL текущего пользователя.
Не поддерживаются произвольные пути, диски, UNC, ADS, `..`, reparse/junction и hardlinked файлы. Подкаталоги с reparse-атрибутами не показываются.
Загрузка идёт в `.ra-part`; resume получает размер частичного файла, commit проверяет размер и SHA-256 и переименовывает без overwrite.
Если остаток относится к другому содержимому, SHA-256 отклонит commit; пользователь должен локально удалить `.ra-part` и повторить.
Хэш загрузки не является подписью автора. Локальные конкурентные изменения каталогов не изолированы от ОС handle-based sandbox; не давайте недоверенным локальным процессам запись в общую папку.
Папки удаляются только пустые. Удаление подтверждается в клиенте; в режиме с локальным согласием также подтверждается на сервере. Для явно разрешённого постоянного доступа дополнительных серверных диалогов удаления нет.

## Логи и остаточные риски

`audit.jsonl` хранится в `%LOCALAPPDATA%\RemoteAdmin\Server` и `Client`, ротация 10 MiB (одна предыдущая копия).
В аудит не входят коды, ключи, ввод, чат, содержимое файлов/буфера. Это локальный журнал, не защищённый от модификации самим пользователем.
По умолчанию файлы и буфер отключены. Сервер слушает все IPv4/IPv6 интерфейсы после явного нажатия кнопки.
Не открывайте порт для всего интернета. Ограничьте firewall или примените свой VPN. Есть ограниченные таймауты и задержка на неверный код, но нет полноценной защиты от DoS.
Выпуск требует независимого security review и подписи. MSI удаляет установленные файлы, но сохраняет данные CurrentUser; удаление `%LOCALAPPDATA%\RemoteAdmin` сбрасывает identity и адресную книгу. Общая папка с пользовательскими файлами не удаляется.
