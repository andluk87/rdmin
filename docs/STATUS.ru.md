# Фактический объём и отличия от исходного ТЗ

Последнее требование: только Windows Server (приложение удалённого доступа) и Windows Client.
Web Admin Panel, Backend, PostgreSQL, Redis, OIDC, организации, централизованный аудит, TURN и связанные API исключены из текущего scope.

## Написано, но пока не проверено сборкой и запуском

- Два WinForms-приложения .NET 8 x64, интерфейс на русском.
- Native C++20 DXGI-захват; GDI fallback при невозможности инициализации DXGI.
- Прямой TCP/TLS 1.2/1.3, проверка вручную переданного SHA-256 сертификата, DPAPI для закрытого ключа.
- 128-битный одноразовый код, TTL 5 минут, обязательное локальное подтверждение, один сеанс, лимит 1 час.
- Просмотр, ввод, выбор монитора, масштаб с сохранением пропорций, fullscreen, ручное качество.
- Общая папка и файловый менеджер, проверка SHA-256, чанки 4 MiB, докачка до 2 GiB.
- Чат, отключаемый Unicode-буфер, локальная адресная книга, аудит начала/конца и файловых операций.
- Docker cross-build, self-contained ZIP, MSI без подписи.

## Не реализовано из оставшихся требований исходного ТЗ

- Windows Service, отдельный session worker, защищённый IPC, unattended access, автозапуск.
- H.264/Media Foundation, WebRTC, ICE/STUN/TURN, автоадаптация битрейта и 30/60 FPS, отдельный курсор DXGI.
- Windows.Graphics.Capture fallback; аппаратный encode/decode.
- Одноразовое криптографическое спаривание с взаимной идентичностью устройства: сейчас сервер аутентифицируется pin, оператор — possession-кодом и локальным согласием, а не своим постоянным ключом.
- Группы/вложенные папки адресной книги, импорт/экспорт, английская локализация, темы, история в UI.
- Автообновления, подпись кода, автоматический reconnect (используется безопасное завершение и новое подтверждение).
- Синхронизация раскладки клавиатуры; VK-клавиши зависят от раскладки удалённой Windows. Для Unicode есть отдельная команда «Ввести текст».
- Передача модификаторов Win/Alt не гарантирована из-за обработки системных сочетаний локальной Windows.
- Управление питанием, корпоративные политики, удалённый терминал.
- Security review, матрица Windows 10/11/Server, нагрузочные и acceptance-тесты.

Прототип не запускает повышенные процессы, не обходит UAC и не захватывает защищённый desktop.
Пользователь должен оставаться вошедшим в Windows и держать сервер открытым.
При смене разрешения/desktop DXGI может завершить сеанс; требуется повторное подключение.
Режим файла — только текущий пользователь Windows, без использования привилегий службы.
Локальные злоумышленники с возможностью менять общую папку конкурентно остаются отдельной угрозой: проверки путей не являются kernel sandbox.

## Проверки текущей задачи

Компиляция, Docker build, установка зависимостей, Windows-запуск и тесты **не выполнялись** по прямому требованию заказчика.
Сделана только проверка структуры исходников и конфигурации без компиляции. Артефактов EXE/MSI здесь нет.
До успешной сборки на VPS и испытаний на двух Windows-машинах нельзя утверждать работоспособность или готовность к эксплуатации.

## Изменения 0.3.0 — сервер управляет аутентификацией и правами

Добавлены серверные учётные записи RemoteAdmin, индивидуальные права, отключение/удаление пользователя, изменение пароля, DPAPI-конфигурация и сохранение порта/метода входа. Клиент требует только адрес и порт, затем показывает вход, определённый сервером. Проверка ключа при первом соединении и последующее pinning остаются обязательной защитой TLS. Приглашения — дополнительный метод, выключенный по умолчанию.

Ранее перечисленные ограничения «обязательный код» и «нет доступа без разового согласия» сняты для новой модели учётных записей. Постоянный доступ реализован только при открытом видимом сервере в текущей пользовательской сессии, с явным разрешением для конкретной записи; Windows Service и worker по-прежнему отсутствуют. Windows/AD/SSPI-аутентификация не реализована. Новый код этой версии не собирался и не запускался в данной среде.
